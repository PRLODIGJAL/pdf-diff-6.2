# PDF 差异对比工具 v6.2

同一份文件的两个版本并排放进来，自动标出**删了什么、加了什么、哪一段挪了位置** —— 一个窗口看完，不用打印两张纸对着比。

标签、说明书（IFU）这类 PDF 版本变更频繁，每次变更都要做一次前后比对，确认「只改了该改的地方」。一份多页文件人工逐页肉眼比对约 30~60 分钟，页数越多越久，还容易漏查。
现在原生类 **12~67 秒**出结果（含 OCR），同时产出差异清单与标注版 PDF，复核范围从「全篇」压到「低档几条」。

## 目录结构

| 目录 | 说明 |
|---|---|
| `mac/` | macOS 版（`.command` 双击启动） |
| `windows/` | Windows 版（`.bat` 双击启动） |

两个目录下都是 `app/` + 一个启动器 + 一份 `说明书.md`，`app/` 内的源码在两个平台**逐字节一致**（平台差异只在启动器与 `app/shell/` 的极少数分支里）。

## 这个仓库里没有 runtime

6.2 是「免装交付」版：完整发布包里自带 Python 运行时（`runtime/`）与离线 wheels，拷到任何电脑双击就能开，不用装 Python、不用联网。
但 `runtime/` 单平台就有 442 MB（Mac），加上离线 wheels 与调试用的 `dev/` 超过 1 GB —— 超过 GitHub 的单文件 100 MB 限制，也没必要进版本库。

**所以这里只放源码**。要能真正运行，二选一：

- 拿内部共享盘 / 内部工具库网页上的完整 6.2 压缩包（含 runtime）；
- 或者在本目录里自己补一个 Python 3.13 环境：`app/` 的依赖见 `app/shell/setup_env.py` 里的依赖清单，用系统 Python 建虚拟环境后把 `runtime/` 指向它即可。

## 功能

- 输入 PDF / 图片（PNG JPG BMP TIFF）/ Word（doc docx）/ Excel（xls xlsx），可混着拖
- 拖进来就能看原件，能翻页缩放，类型当场判定
- 三种看法：**并排**双栏、**滑动**（中间一根线左右拖）、**叠加**（两版来回闪）
- 四色图层，三个勾可各自开关：删减（红）/ 新增（绿）/ 位移（浅蓝）/ 待判定（紫）
- 内置 OCR 文字识别（`app/engine/models/` 下的 ONNX 模型），转曲 / 图片区走 OCR 兜底
- 导出 JSON（页号 / 类别 / 文本 / 坐标）与原图标注版 PDF
- 全程离线，**不联网、不改原件**

## 四条硬门槛（故意严）

1. 只能同格式比（跨格式刷出来的差异大半是「转换差」，不是「用户改的」）
2. 页数必须相同
3. 纯扫描件不参与对比
4. 拼接 PDF 里的扫描页自动跳过

## 更新记录

**2026-11-09 ｜ 修掉 Windows 上「自检全绿、界面却打不开」**
双击启动器，六项自检全 OK，界面刚搭一半就退出，报 `bad button number "6"`。
原因是横向滚轮绑了鼠标 **6/7 号键位**，而 Windows 自带界面对应的 Tk **8.6 只认 1~5 号**，解析事件那一刻就抛错；
Mac 那套是 **Tk 9.0**，同样的写法从来不报 —— 所以问题只在 Windows 露头。
现在改成「能绑就绑、绑不上跳过」，不影响任何功能（Windows 的横向滚动本来就靠 Alt+滚轮）。**对比逻辑一个字节没动。**

**2026-11-06 ｜ v6.2 免装交付**
包内自带 runtime 与离线 wheels；启动器只留一个，第一次打开跑几秒自检，之后秒开；启动器自己修执行权限和下载隔离标记。
